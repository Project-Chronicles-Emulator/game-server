# Received request features, interactions and mounts (2026-10-29)

This batch answers requests that live original clients already send to the emulator but that
previously had no owner, no reply or only a silent drop. The scope came from a metadata audit of
retained server logs (58 request types). Ordinary movement and accepted skill-stage reports
legitimately have no direct reply; no acknowledgement was invented for them.

It is integrated on top of the accepted mounted-session repair (`f44f51f`, documented in
[session-delay-repair-20261029.md](session-delay-repair-20261029.md)) and the deployed housing
repair (`6a10874`). The committed-life cache, single gameplay timer, frame filtering and housing
board/contract behavior are preserved unchanged.

## Generated runtime profiles

The release must carry these regenerated files; the server otherwise starts without the new
behavior or with stale combat bounds:

- `data/generated/world-mobs/definitions.json` and `data/generated/tutorial/definitions.json`:
  regenerated with the player motion and adapted-rotation export. A full JSON comparison with the
  deployed files shows only added `player_motion`/`adapted_rotations` stage entries and added
  source fingerprints.
- `data/generated/adventure/definitions.json` (new).
- `data/generated/npc-reactions/definitions.json` (new, build and source-dump checked at load).
- `data/generated/processing/definitions.json`: adds `requires_learning`.
- `data/generated/loot/definitions.json`: recipe items are now persisted stackable loot instead of
  skipped groups.

## Known limits

- Achievements: only character level, quest completion count and specific adventure-object goals
  are evaluated from stored facts. PlayRecord counters (318 goal rows), adventure counts by zone,
  weighted logbook percentage, expertise level and player kills are parsed but refused with the
  matching achievement error. Client-reported counts are never trusted.
- Eight authored chest placements stay unavailable because the client data is invalid: map 20702
  objects 20070100-20070103 name missing ExpertiseReward rows, and map 30711 objects
  20075000-20075003 contain malformed reward JSON. They grant nothing and are not completed.
- Gliding has no authoritative flight physics. Crowd control covers only the modelled stun ailment;
  combat-state, flight-tool and zone restrictions have no server evidence and are not enforced.
- NPC reaction state is bounded at 4096 actors. Finished stationary reactions are dropped first,
  then finished private-instance reactions; shared patrol offsets are kept.
- Observers whose own patrol later reaches the paused phase can receive the reaction a second
  time with the same start tick.
- Shared-world level triggers (20084) remain unhandled outside the tutorial: map-move and
  cutscene destinations are missing from the recovered data and client dialogue tasks have no
  server packet.
- Preorder rewards, payments and entitlements do not exist.

## Verification

- Default Release suite: 2,061 registered cases, 0 failures, 127 environment-gated skips.
- Same suite with the real catalog and the regenerated profiles: 1,991 executed, 70 skipped,
  one failure: `NativeWorld.TradeRunFromWatchersPostToSeaglassHarborPaysTheRouteReward` cannot find
  its NPC in the deployed map-9012 placement file. The identical failure occurs in the
  housing branch built without this batch, so it is pre-existing test data drift.
- Isolated PostgreSQL cluster (`tools/test_postgres.py`): migration, server restart smoke, account
  tool and 12 named repository cases, including recipe and achievement receipts, passed.
- Python exporter tests: received features 5, processing 10, loot 38, tutorial 5, combat 93 passed.
- Module include check: no new violations.

No original-client trial of these behaviors happened before deployment. Offline packet encoding,
synthetic TLS sessions and HTTP health do not establish original-client acceptance.

## Deployment

Deployed 2026-10-29 21:35 UTC from `e62f9aa` on top of the live housing repair, with
user-authorized direct deployment. A fresh verified database backup was restored to an
isolated cluster first: the additive migration raised schema 34 to 36, repeated cleanly and
preserved every counted row. On the live host the previous binary, profiles, migration and
manifest were saved for rollback, players received an in-game restart notice and the backend
shut down gracefully. After the switch the running binary, all 547 manifest files, both
listeners, health, preserved HTTP route statuses, schema 36, unchanged player-state counts and
the new startup profile lines (54 adventure maps, 612 reacting civilians, 106 achievements)
were verified. No warnings appeared in the fresh server log. Original-client acceptance of the
new behaviors is still pending.
